# 04. Information Architecture (IA)

> 5개 공개 페이지 + 새가족 + 어드민. GNB 구조와 페이지별 섹션 우선순위.
> 시안 단계에서 잠금된 구조를 본 개발에 그대로 승계.

## 전역 GNB

```
[로고] 교회소개 | 예배와 교육 | 목양과 사역 | 교회 활동 | 새가족 [생방송 보기 CTA]
```

- **새가족** 메뉴는 시각적 강조 (다른 색 또는 우측 정렬) — 새신자 진입 최우선
- **생방송 보기** CTA는 헤더 우측 고정 — 주일/수요예배 시간엔 빨간 점 활성 (`context/components/interactive/live-badge.md`)
- 데스크탑: 드롭다운 2뎁스 (`context/components/layout/header.md`)
- 모바일: 햄버거 → 풀스크린 메뉴 (`context/components/layout/mobile-nav.md`)

### GNB 상호작용 — 잠금 (2026-08-12)

검토 화면 `/dev/gnb`(STEP 1·2)를 놓고 디자이너(박정민 집사)와 1:1 합의. **다수 의견 수렴을 하지 않고
둘이 결정하는 방식**을 택함 (`church-approval-strategy` — 디자인 결정권은 위임받은 상태).

| 항목 | 결정 | 사유 |
|---|---|---|
| 메가메뉴 펼침 방식 | **B · 올린 대메뉴 하나만 펼침** (사랑의교회식) | 방문자는 이미 5개 중 궁금한 하나를 골라 올린 상태 — 그것만 보여주는 게 읽기 편하고 패널도 깔끔. A(전체 5열 노출)·C(좌측 5개 유지 하이브리드)는 폐기 |
| 대메뉴 클릭 | **① 클릭 불가.** 링크가 아니라 hover/focus로 패널을 여는 컨트롤. 클릭 불가임을 **색으로 구분** | 대메뉴 랜딩 페이지(허브 요약 ②·전체 나열 ③)를 만들지 않음. ③은 모바일에서 13화면까지 길어져 폐기. 하위가 패널에 다 보이므로 도달성 손실 없음 |
| 대메뉴 도달성 보증 | 하위 항목이 전부 해당 페이지의 앵커(`/worship#times` 등)라 1클릭 도달. **새가족만 패널 안에 `새가족 안내 바로가기 →` CTA 유지** | 새신자 동선은 클릭 불가 정책의 예외 없이도 보장돼야 함 |
| 모바일 메뉴 | 햄버거 → **드릴다운 2단**(대메뉴 5개 목록 → 탭하면 그 메뉴 하위만 전체 화면 + `← 전체메뉴`) | 모바일엔 hover가 없어 B안을 그대로 못 씀. "하나만 딱 보여준다"는 B안 성격을 모바일로 옮긴 형태. 아코디언은 『목양과 사역』(L2 2 + L3 11)에서 한 번 펼치면 화면을 꽉 채워 폐기 |
| 모바일 `새가족` 위치 | **맨 아래 유지** (기존 자리) | 디자이너 판단. 대신 highlight 색으로 구분 |

### 2차 목차 승계 완료 (2026-08-23)

`lib/nav-v2.ts` 검토 초안을 **`lib/nav.ts`로 승계하고 초안 파일은 삭제**했다. GNB 데이터 구조가
`children[]` 평면에서 `groups[].items[]` 2단이 됐다 — 메가메뉴 열 = L2 그룹, 모바일은 2단 화면 안 소제목.

- 대메뉴는 **5개 고정. 신설 금지.** 새 항목은 기존 대메뉴 안 그룹/항목으로 흡수한다.
- 뎁스 상한 L3 유지. L4는 페이지 안 탭(예배 실황 6종 · 영상뉴스 3종 · 자료실 4종 · 전도회 남/여).
- 신설 라우트 13종은 `StubPage`로 먼저 깔았다 (메가메뉴 링크 404 방지):
  `/education` `/ministry` `/giving` `/worship/live` `/activity/{weekly,bulletin,news,denomination}`
  `/church-admin{,/notice,/resources,/apply,/reserve}` `/privacy`
- 신설 라우트에는 콘텐츠 이관 전까지 **현행 사이트 대응 URL**(`lib/nav.ts`의 `legacy`)을
  "현재 홈페이지에서 보기" 링크로 노출한다. 이관 완료 시 `legacy` 값을 지운다.
- **새가족 온라인 등록 폼 노출 중단** (2026-08-09 결정의 코드 적용). `/newcomer`의 `overrides`와
  `/care`의 폼 임베드를 주석으로 걷어냈고, 폼 코드·스키마·서버액션은 보존했다. 복구 방법은 각 파일 주석에 있다.

### 현행 사이트 잔여 메뉴 이관 — 기본값 적용 (2026-08-23)

현행 6개 대메뉴를 4+1로 줄이면서 갈 곳이 없던 항목들을, **현행 사이트 전수 분석**(전 하위 페이지 본문·
접근권한 확인)에 근거해 배치했다. 근거·현행 URL 매핑·폐기한 대안은
[`docs/meetings/2026-08-23-현행사이트-메뉴-전수분석.md`](../docs/meetings/2026-08-23-현행사이트-메뉴-전수분석.md).

교회 회신을 기다리지 않고 **기본값으로 적용하고 이의를 접수하는 방식**(`church-approval-strategy`)을 택했다.

## 페이지별 IA (스크롤 순서)

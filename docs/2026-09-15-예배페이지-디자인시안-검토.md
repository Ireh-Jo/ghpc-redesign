## 4. 결정 기록 (2026-09-15 · 사용자 위임 사항)

### 4-1. 생방송 on/off — 수동 토글 폐지, 유튜브에 위임

현행은 사람이 켜고 껐다(끄는 걸 잊으면 방송이 끝났는데 "방송 중"). 미디어팀 2명이 주 3회 토글하는 구조는 반드시 사고가 난다.
**아무도 손대지 않아도 맞는 2층 구조**로 바꿨다.

| 층 | 무엇이 정하나 | 틀리면 |
|---|---|---|
| 영상 내용 | ~~유튜브 채널 라이브 임베드 (`embed/live_stream?channel=`)~~ → **2026-09-16 폐기.** 실제 방송 중에도 오류 화면이 떠서, 서버가 채널 `/live`에서 라이브 영상 ID를 읽어 임베드하는 방식으로 교체 (`lib/youtube-live.ts`) | 못 찾으면 안내 화면으로 내려앉음 |
| 화면 배치 (플레이어 vs 다음 방송 안내) | 편성표 + 서울 시각 (`LIVE_SCHEDULE`) | 배치만 어긋나고 내용은 맞다 |

API 키도 서버도 운영 입력도 없다. 편성표 밖 특별집회까지 정확히 잡으려면 YouTube Data API로 승격하면 되고,
그 설계는 `context/features/live-streaming.md`에 이미 있다. **지금 단계에서는 과투자.**

### 4-2. 모바일 동선

시안에 없던 부분은 이미 만들어 둔 것으로 채웠다 — 추가 시안 없이 동작한다.

- **GNB**: 헤더 햄버거 → 드릴다운 2단(`MobileNav`). 시안엔 햄버거가 없지만 없으면 이동이 불가능하다.
- **탭**: 앵커바가 헤더 아래 sticky + 가로 스크롤. 라벨 3개(예배 및 모임 안내 / 생방송 / 특별순서)는 375px에 들어간다.
- **표**: 카드형 전환(§3-2). **영상**: 1열 그리드, 분류 칩은 가로 스크롤.
- 이 화면에서 모바일 전용으로 더 필요한 건 없다고 본다.

### 4-3. 타이포

시안의 NanumSquare는 채택하지 않고 **Pretendard 단독**(`context/design/02-typography.md` 잠금) 유지.

### 4-4. 영상 목록 자동화 — 지금은 목업, 자동화는 유튜브 재생목록으로 (조사 결과)

지금 `lib/worship-videos.ts`는 **하드코딩 목업**이다(현행 게시판에서 옮긴 실제 영상). 갱신하려면 코드를 고쳐야 한다.
2026-09-15 채널(@ghpc)을 확인해 보니 **재생목록이 이미 살아서 관리되고 있다**:

| 재생목록 | 편수 | 갱신 |
|---|---|---|
| `예배실황2(2026-02-15부터)` | 49 | 어제 |
| `예배특송` | 918 | 어제 |
| `구역공과` | 260 | 오늘 |
| `하박국 강해` | 17 | 3일 전 |
| `집회/특강` · `갈라디아서강해` · `절기특송` 등 | — | — |

그리고 영상 제목이 **기계가 읽을 수 있을 만큼 규칙적**이다:
`주일낮예배실황 2026-09-13 | 경향교회` · `특송 2026-09-13 | 나를 지으신 주님 | 김지수 집사`

**영상 설명란까지 확인한 결과(2026-09-15 추가 조사) — 예배 실황도 완전 자동화가 된다.**
설명란 머리 세 줄이 이미 고정 양식이고 **미디어팀이 지금도 매주 그렇게 쓰고 있다**:

```text
주일낮예배실황 2026-09-13
경향의 강단(38) (2026년 9월 13일 / 주일대예배)
설교: 다시 일어설 힘이 없을 때(열왕기상 19장 1-18절) 신승욱 목사
```

`설교: {제목}({본문}) {설교자}` 한 줄만 파싱하면 게시판에 있는 정보가 전부 나온다.
주일밤·수요밤·금요밤기도회(강해) 영상도 같은 양식이었다.

→ 결론:
- **추가 입력 없이 100% 자동화 가능.** 유튜브에 올리는 지금 방식 그대로 두면 홈페이지가 따라온다.
- 전제는 **설명란 양식 유지**다. `설교:` 줄이 빠진 영상은 제목만으로 폴백(제목·날짜만 표시)하고
  어드민에서 덮어쓸 수 있게 둔다.
- 부수 발견: 현행 `강해` 게시판은 설명란 머리글이 `금요밤기도회`다 — **강해 = 금요밤기도회 설교**.
  분류 라벨을 `강해`로 둘지 `금요밤기도회`로 바꿀지 확인 필요.
- 필요한 것: YouTube Data API 키 1개(무료)와 재생목록 ID 몇 개. `playlistItems.list`가 1 unit이라
  10분 캐시면 일 quota(10,000)의 1%도 안 쓴다.
- `구역공과` 재생목록이 오늘도 갱신된다 → §7의 "구역장성경공부 행 삭제" 확인에 참고.

> DECISION NEEDED: 1차 오픈 범위에 유튜브 동기화를 넣을지. 안 넣으면 어드민 입력(현행과 동일)으로 가고,
> 넣으면 `lib/youtube.ts` + 키 발급이 선행된다. **권장: 특별순서만 먼저 자동화**(입력 0) → 예배 실황은 어드민.

## 5. 제안 — 모션·포커싱 (`context/design/06-motion.md` 준수: 페이드·호버만, 패럴랙스 금지)

1. **히어로**: 배경은 고정(패럴랙스 금지). 타이틀 → 브레드크럼 순서로 `opacity 0→1 / translateY 8px→0`, 400ms ease-out, 60ms stagger, **1회만**.
2. **탭**: sticky (`top-16 md:top-20`, 헤더 바로 아래). 활성 표시는 밑줄 인디케이터 `transform` 200ms 슬라이드. 탭 전환 시 패널 `opacity 0→1` 150ms.
   - 탭 상태를 **URL 해시/쿼리에 동기화**(`?tab=live`) — 공유·새로고침·뒤로가기 보존.
   - 키보드: `role="tablist"` + ←/→ 이동 (Radix Tabs 사용).
3. **표**: 행 `hover:bg-brand-bg` 200ms. 표 블록 진입 시 페이드업 1회. 모바일 가로 스크롤 시 우측 그라데이션 힌트.
4. **"지금 이 예배" 포커싱** — 애니메이션보다 이게 실효가 크다. 현재 요일·시각과 맞는 행에 `brand-support` 좌측 4px 바 + 옅은 배경, 라벨 `진행 중`. 생방송 판정 로직(`context/features/live-streaming.md`)과 같은 소스를 쓴다.
5. **LIVE 도트**: 방송 중일 때만 `brand-point` 2초 펄스 (면적 작아 레드 가이드 부합).
6. **유튜브**: 썸네일 → 클릭 시 iframe 로드(lite). 호버 시 재생 버튼 `scale 1.05`.
7. **포커스 링**: `focus-visible:ring-2 ring-brand-accent ring-offset-2` 전역. `prefers-reduced-motion`에서 모든 transition 0ms.

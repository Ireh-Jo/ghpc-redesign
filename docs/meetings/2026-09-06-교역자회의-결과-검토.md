## 2. 항목별 검토

### 2-1. ① 새가족 — 구성은 완료, **순서**가 실제 변경사항

메뉴 구성 자체는 2026-08-23 2차 목차 승계 때 이미 회의 결과대로 갔다.
`lib/nav.ts` 상단 주석 및 `care` 섹션 주석 — 목양에서 새가족을 통째로 `새가족` 대메뉴로 옮기고
**교차링크 한 줄조차 남기지 않아** 도달 경로를 하나로 만들었다.

놓치기 쉬운 차이는 **나열 순서**다.

| | 순서 |
|---|---|
| 회의 결과 | 교회소개 · **새가족** · 예배와교육 · 목양과사역 · 교회활동 |
| 현재 코드 | 교회소개 · 예배와 교육 · 목양과 사역 · 교회 활동 · **새가족**(강조색) |

현재 배치는 2026-08-12 디자이너(박정민 집사)와 1:1로 **잠근 결정**이다
(`context/04-information-architecture.md` § GNB 상호작용 — 모바일도 맨 아래 유지 + highlight 색 구분).

→ 회의 문구가 **배치 순서 지시**인지 단순 나열인지 확인 필요. 순서 지시라면 데스크탑·모바일 둘 다 바뀌고
8/12 잠금이 풀린다. 작업 자체는 `NAV` 배열 순서 한 줄.

### 2-2. ② 집사회·권사회 → 섬기는 사람들 — **권장**

참고로 주신 사랑의교회 페이지(`sarang.org/info/people_d.asp`)를 2026-09-06 직접 확인했다.

- **개인 명단·사진이 아니라 조직 소개형**이다. "시무권사 2,188명"처럼 **직분별 인원 수만** 표기하고
  실명·사진은 공개하지 않는다 (검색 기능으로만 조회).
- 사랑의교회 GNB가 `교회소개 / 설교·찬양 / 목양·사역 / 교육·훈련` 로 우리 2차 목차와 거의 같다.

이게 중요한 이유:

1. **개인정보 이슈가 없다.** 집사회 192명·권사회 470명(2026-08-23 전수조사 수치)을 "N명"으로 표기하면 된다.
2. 우리가 미해소로 남겨둔 **새가족 수료자 명단**도 같은 해법("N명"만 노출)을 권고해둔 터라 일관된다.
3. 2026-08-23에 집사회·권사회를 `목양`에 넣은 근거는 "전도회와 같은 조직 소개 템플릿"이었는데,
   **직분 조직(집사·권사) / 활동 조직(전도회)** 로 가르는 회의안 논리도 성립한다.

작업량: `lib/nav.ts` 항목 2개 이동 + 앵커 `/care#deacons` `/care#kwonsa` → `/intro#deacons` `/intro#kwonsa`
+ IA 문서 갱신. **30분.** 담임목사 확인이 필요한 항목이라 회신 전까지 착수하지 않는다.

> 함께 여쭐 것: 집사회·권사회가 섬기는 사람들로 가면 **남/여전도회는 왜 목양에 남는지**의 기준.
> 답이 "직분 조직 vs 활동 조직"이면 그대로 간다. (§5-1)

### 2-3. ③ 청년회 = 교육 — **미결 질문 1건 해소**

`lib/nav.ts`의 `OPEN_QUESTIONS`에 있던 "청년회는 연합기관인가 교육인가"(현행 사이트=연합기관 / 2차 목차 PPT=교육)가
**교육으로 확정**됐다. 잠정으로 이미 교육에 두고 있었으므로 **코드 변경 없음** (`/education#young-adult`).

**목양 중복 게재는 반대한다.** 새가족을 통합할 때 "교차링크 한 줄도 남기지 않아 도달 경로를 하나로 만든다"를
원칙으로 세웠는데, 청년회만 GNB 두 곳에 나오면 그 원칙이 깨지고 콘텐츠 수정 시 두 곳을 관리해야 한다.

→ 대안: **GNB가 아니라 `/care` 페이지 안에 카드 링크 한 개.** 목양 맥락에서 청년회로 가는 길은 열어두되
GNB 항목은 늘리지 않는다. 9/20에 이 안을 제출한다.

### 2-4. ④ 소모임 제거 — 이미 그렇게 돼 있음

현재 `목양` 그룹 = 구역모임 · 전도회 · 집사회 · 권사회 · 동호회.
'소모임'이라는 중간 계층은 2차 목차 승계 때 이미 없앴다.

②가 반영되면 **구역모임 · 전도회 · 동호회** 3개로 회의안과 정확히 일치한다.
전도회는 남/여를 페이지 안 탭으로 내린 상태고, 회의안도 '전도회' 단일이라 맞는다.

### 2-5. ⑤ '문화' 대메뉴 — **코드 비용은 없다. 문제는 콘텐츠다**

> **정정 (2026-09-06).** "대메뉴 5개 고정·신설 금지"(2026-08-23)는 **기술적 제약이 아니라 사용자 지시**다.
> 철회 가능한 결정이며, 6개로 늘려도 손볼 코드가 사실상 없다.

**기술 검토 결과 — 6개는 문제없이 들어간다:**

- 헤더는 `flex gap-8` + 컨테이너 max-width 1200px. '문화'는 두 글자라 여유 있게 들어간다
  (`components/layout/header.tsx` 주 메뉴 `<ul>`)
- 메가메뉴 열 클래스 `GROUP_COLS`가 **4열까지 정의**돼 있고, 회의안 문화 목차가 정확히 4그룹
  (취미·찬양·행사·시설)이라 그대로 맞는다
- 모바일은 드릴다운 목록이라 한 줄 늘어날 뿐이다

**실제 문제는 네 가지다.**

**(1) 절반이 빈칸에서 시작한다.**

| 회의안 항목 | 현재 상태 |
|---|---|
| 동호회 | 이미 `목양과 사역 > 동호회` |
| 시니어스쿨 | 이미 `예배와 교육 > 경향시니어스쿨` |
| 교구친선리그 | 이미 `/activity/news` 탭 (2026-08-23 배치) |
| 만나의집 카페 · 키즈그라운드 | 이미 `교회소개 > 교회 시설`. 키즈그라운드는 시설 예약 대상이기도 |
| 문화교실 · 인지저스 · 샛별합창단 · 셀라오케스트라 · 뮤지컬 · 송년음악회 · 사랑의모임 · 봉사의모임 | **현행 사이트 GNB·사이트맵 어디에도 없음** — 원고·사진 0에서 시작 |

재배치 5 + **신규 창작 8**이다. 대메뉴는 사이트에서 가장 눈에 띄는 자리인데
**거기가 제일 비어 있으면 없는 것보다 나쁘다.** 한 번 눌러보고 비면 다시 누르지 않는다.

**(2) 분류 축이 섞인다.** 현재 5개는 "무엇을 하는가" 축(예배/교육, 목양/사역, 활동)이고 문화는
"어떤 성격인가" 축이다. 축이 섞이면 **같은 것이 두 군데 있게 된다** — 동호회가 목양에도 문화에도 들어가는 게
그 증거이고 시니어스쿨·교구친선리그·키즈그라운드도 같다. 교인은 "이건 어디 있더라"를 매번 두 번 생각하고,
우리는 수정할 때마다 두 곳을 고쳐야 한다.

**(3) 새가족 강조와 방향이 반대다.** 같은 회의의 ①(새가족을 2번째로)은 더 눈에 띄게 하자는 뜻인데,
메뉴를 하나 더 붙이면 대비가 줄어든다. 두 결정이 서로 당긴다.

**(4) 되돌리기가 비대칭이다.** 하위 → 대메뉴 **승격은 쉽다**(한 줄). 대메뉴 → 하위 **강등은 어렵다** —
주소가 바뀌어 링크·검색 노출·교인이 외운 위치가 다 깨진다.

**→ TF 권고: "6개는 안 된다"가 아니라 "콘텐츠가 모인 뒤 6번째로 승격하자".**
그동안의 자리는 아래 두 안 중 하나. 사용자·담임목사님이 지금 6개로 가자고 판단하시면 그대로 만들 수 있다 —
코드 비용은 없다.

| 대안 | 내용 | 장점 |
|---|---|---|
| **A. `교회 활동` 안 그룹** | 대메뉴 5개 유지, 문화를 세 번째 열로 | 기존 구조 그대로. 중복 항목은 원본 1곳 + 문화에서 링크만 |
| **B. GNB 밖 `/culture` 랜딩** | 메인 배너·"자주 찾는 메뉴"로 진입 | 찬양·행사처럼 계절성 있는 콘텐츠에 맞고, 나중에 대메뉴 승격이 쉽다 |

> 그대로 옮겨 쓸 수 있게 정리했다. **디자인 판단이 아니라 사실·방침 확인**만 담는다.

### 5-1. 담임목사님 확인 필요

**① 집사회·권사회를 '섬기는 사람들'에 넣을 때, 무엇을 싣습니까?**
참고로 주신 사랑의교회는 개인 명단·사진 없이 **"시무권사 2,188명"처럼 인원 수만** 표기하는 방식이었습니다.
같은 방식(설립목적·역할·활동사진 + 인원 수)으로 이해하면 되겠습니까?
— 개인 실명·사진을 싣는 방식이라면 662명(집사 192 · 권사 470)의 **개인정보 동의 절차가 먼저** 필요합니다.

**② 집사회·권사회가 '섬기는 사람들'로 가면, 남전도회·여전도회는 왜 '목양'에 남습니까?**
"집사·권사는 직분 조직, 전도회는 활동 조직"이라는 기준이면 그대로 진행하겠습니다.
기준을 정해두지 않으면 나중에 다른 조직이 생길 때 매번 다시 논의하게 됩니다.

**③ '문화' 항목을 지금 대메뉴로 만들지, 콘텐츠가 모인 뒤 만들지 정해주십시오.**
지금 만드는 것도 **기술적으로는 문제없습니다**(대메뉴 6개 가능, 추가 개발 비용 없음).
다만 목차 14개 중 **8개는 현재 사이트에 원고·사진이 전혀 없고**, 5개는 이미 다른 메뉴에 있는 항목입니다
(동호회·시니어스쿨·교구친선리그·만나의집 카페·키즈그라운드).
같은 항목이 두 메뉴에 나오면 수정할 때마다 두 곳을 고쳐야 하고, 교인도 어디서 찾을지 헷갈립니다.
TF는 **당분간 '교회 활동' 안에 두거나 별도 페이지로 두었다가, 내용이 채워지면 대메뉴로 올리는 것**을 권합니다
(하위 → 대메뉴 승격은 쉽지만, 반대는 주소가 바뀌어 링크가 깨집니다).

### 5-2. 교역자 회의 확인 필요

**④ 메뉴 나열 순서 — '새가족'을 두 번째에 두라는 뜻입니까?**
회의 결과가 `교회소개 / 새가족 / 예배와교육 / 목양과사역 / 교회활동` 순으로 적혀 있습니다.
현재 개편안은 **새가족을 맨 뒤에 두고 다른 색으로 강조**하는 방식입니다(디자인 협의로 정한 배치).
순서를 바꾸라는 뜻이면 그대로 반영하겠습니다. 단순 나열이면 현재 배치를 유지하겠습니다.

**⑤ 청년회를 '목양'에도 넣는 건 다시 생각해주시길 요청드립니다.**
같은 항목이 메뉴 두 곳에 나오면 내용을 고칠 때마다 두 곳을 고쳐야 합니다.
대신 **'목양과 사역' 페이지 안에 청년회로 가는 링크 카드**를 두는 방식을 제안합니다.
메뉴는 '교육' 한 곳으로 유지하면서 목양 쪽에서도 찾아갈 수 있습니다.

## 6. TF 문의사항 답변 — '문화' 비공개 운영

**결론: 가능합니다.** 다만 "비공개"가 세 가지 뜻일 수 있고 비용이 크게 다릅니다.

| 단계 | 뜻 | 비용 |
|---|---|---|
| **1. 메뉴에서만 감추기** | 메뉴에 뜨지 않고 검색에도 걸리지 않음. **주소를 아는 사람만** 볼 수 있음 | **반나절** (`lib/nav.ts` 플래그 한 줄 + 페이지 검색 차단 설정) |
| **2. 완전 비공개 (로그인해야 봄)** | 교인 인증을 통과해야 열람 | 회원 인증 기능이 **아직 없음**(Supabase 미연결). **1차 오픈 범위 밖** |
| **3. 오픈** | 공개 전환 | **플래그 한 줄 삭제.** 주소·페이지 그대로라 링크도 안 깨짐 |

**→ 1번을 권합니다.** 교역자 내부 검토·공유용으로는 충분하고, 오픈이 한 줄이라 되돌리기도 자유롭습니다.
2번(로그인)을 요구하시면 다른 일정이 밀립니다.

**회신에 함께 붙일 단서 3가지:**

1. **감춰둔 페이지도 원고·사진은 만들어야 열립니다.** 감춘다고 콘텐츠 부담이 없어지지 않습니다.
2. **"추후 풍성해지면"의 기준을 지금 정해두지 않으면 영원히 안 열립니다.**
   예: "항목당 소개글 300자 + 사진 4장이 모이면 오픈" — 9/20에 확정 제안.
3. **항목 구성이 미확정이라면, 만들어놓고 감추는 것보다 아직 안 만드는 쪽이 되돌리기 쉽습니다.**
   대메뉴 자리를 먼저 잡으면 주소 구조가 굳어집니다.

## 0. 왜 미뤄도 되는가 / 언제까지 미뤄도 되는가

- **미뤄도 되는 이유:** 공개 화면은 이미 다 만들어져 있고, 데이터만 파일에서 읽고 있다.
  두 컴포넌트(`MainBanner`·`NoticeList`)는 **배열만 받는 구조**라 나중에 출처만 갈아끼우면 화면은 안 건드린다.
- **미루면 생기는 비용:** 공지는 매주, 배너는 행사마다 바뀐다. 어드민이 없으면 **그때마다 이레가 코드 수정 + 배포**를 해야 한다
  (`lib/notices.ts`·`lib/main-banners.ts`). 옵션 B를 택한 이유 자체가 이 부담을 없애려던 것이다.
- **한계선:** **사이트 오픈 전에는 공지·배너 두 화면이 있어야 한다.** 나머지 어드민(설교·주보·일정·섬기는 사람들)은
  오픈 후로 미뤄도 된다 — 그쪽은 아직 목업/스텁이라 어차피 콘텐츠 이관이 선행이다.

## 2. 착수 전에 확정할 결정 4건

| 결정 | 지금 상태 | 정해야 할 것 |
|---|---|---|
| **공지 카테고리** | `posts.category`에 `notice`가 **없다** (`news/video_news/members/denomination` 넷뿐) | `notice` 추가할지, 공지를 별도 테이블로 뺄지 (권고: `posts`에 카테고리 추가) |
| **배너 테이블** | **아예 없다** | 아래 §3-S2의 `banners` 스펙 확정. 특히 **게시 기간(`starts_at`/`ends_at`)을 넣을지** — 넣으면 행사 배너가 날짜 지나면 자동으로 내려가서 미디어팀 손이 덜 간다 (권고: 넣는다) |
| **어드민 디자인 톤** | 미정 (`admin-ui.md` §미정) | 공개 페이지와 같은 톤 vs 어드민 전용 미니멀 (권고: 전용 미니멀 — 만드는 시간이 짧다) |
| **로그인 방식** | 미정 | 이메일 매직링크(비밀번호 없음) vs 이메일+비밀번호 (권고: **매직링크** — 미디어팀이 비밀번호를 잊어도 막히지 않는다) |

## 3. 작업 단계 — 순서대로

### S1. 연결 기반

- `npm i @supabase/supabase-js @supabase/ssr` (`guardrails/03-tech-constraints.md` 화이트리스트 확인)
- `lib/supabase/server.ts` (RSC/Server Action용 · anon 키 + 쿠키 세션)
- `lib/supabase/admin.ts` (**service_role · 서버 전용**. 클라이언트 번들에 절대 들어가면 안 된다)
- `lib/supabase/client.ts` (브라우저용 · anon)
- `middleware.ts` — 세션 갱신 + `/admin/*` 가드
- **검증:** 아무 RSC에서 `select 1` 성공 · `next build` 통과

### S2. 스키마 · RLS 마이그레이션

`supabase/migrations/*.sql`로 관리 (대시보드에서 손으로 만들지 않는다 — 재현·리뷰 불가).
**1차 범위는 5개 테이블만.** 나머지(`services`·`sermons`·`events`·`bulletins`·`staff`·`ministries`)는 콘텐츠 이관 때.

| 테이블 | 용도 | RLS |
|---|---|---|
| `posts` (+`notice` 카테고리) | 공지사항 · 소식 | 익명 SELECT(`published=true`) / 어드민 ALL |
| `banners` **(신설)** | 메인 중앙 배너 | 익명 SELECT(게시 기간 안 + `published`) / 어드민 ALL |
| `newcomer_submissions` | 새가족 등록 (**개인정보**) | 익명 INSERT만 · SELECT 금지 / 어드민 SELECT |
| `form_submissions` | 신청 폼 4종 (**개인정보**) | 위와 동일 |
| `profiles` 또는 이메일 화이트리스트 | 어드민 판정 | 본인 SELECT만 |

`banners` 컬럼 초안:
`id · image_url · image_url_mobile · alt(필수) · href · starts_at · ends_at · sort · published · created_at`

- RLS 패턴은 `context/03-data-model.md` §RLS 정책 작성 패턴 그대로
- Storage 버킷 `banners`(공개 읽기) · `submissions`(비공개) 생성
- **검증:** anon 키로 개인정보 테이블 SELECT가 **막히는지** 반드시 확인 (`guardrails/04-security-privacy.md`)

### S3. 어드민 골격

- `/admin/login` (매직링크) · `/admin` 레이아웃(좌측 네비) · 권한 없는 접근 차단
- 공통 목록/폼 패턴 — shadcn DataTable + Form + zod (`admin-ui.md` §공통 패턴)
- **검증:** 비로그인 `/admin` 접근 시 로그인으로 튕김 · 화이트리스트 밖 계정은 로그인해도 차단

### S4. `/admin/posts` — 공지사항 (**1순위**)

- 목록(카테고리 필터) · 작성/수정 · **게시/숨김 토글** · 삭제(확인 단계)
- 문구는 미디어팀 언어로: "게시" / "임시저장" / "숨김" (`admin-ui.md`)
- **검증:** 공지 하나 작성 → 메인 `/`에 60초 안에 뜬다

### S5. `/admin/banners` — 메인 배너 (**1순위**)

- 목록(정렬 드래그 또는 `sort` 숫자) · 이미지 업로드(Storage signed URL) · 게시 기간 · 게시/숨김
- **업로드 규격 안내를 화면에 박아 둘 것**: PC 2400×750(3.2:1) · 400KB 이하 · 모바일 크롭 별도
  (원본 그대로 올리면 10MB — `lib/main-banners.ts` 주석 참고). 가능하면 **업로드 시 자동 리사이즈**
- **alt 텍스트 필수 입력** — 배너 문구가 이미지에 박혀 있어 유일한 접근 경로다
- **검증:** 배너 교체 → 메인에서 순서·기간대로 노출

### S6. 공개 화면 seam 교체 (여기서 목업 파일이 사라진다)

| 지금 | 바꿀 것 |
|---|---|
| `lib/notices.ts` | `posts`에서 `notice` 최신 N건 쿼리 → 파일 삭제 |
| `lib/main-banners.ts` | `banners`에서 게시 중인 것 쿼리 → 파일 삭제 (이미지 규칙 주석은 어드민 화면 안내로 옮김) |
| `app/(site)/page.tsx` | 위 두 쿼리를 `await`하도록 (이미 RSC라 구조 변경 없음) |
| `public/banners/*.jpg` | Storage로 이관 후 정리 |

- 캐시: 메인에 `revalidate` 부여 또는 어드민 저장 시 `revalidatePath('/')` (권고: **후자** — 즉시 반영)
- **검증:** 어드민에서 바꾸면 메인에 반영 · 배포 없이

### S7. 폼 스텁 해제 (개인정보 — 신중히)

- `app/_actions/newcomer.ts` · `app/_actions/apply.ts`의 `TODO(Supabase)` INSERT 살리기
- `/admin/submissions` — 연락처 마스킹 · 처리 완료 토글 · **다운로드 로그** · 보존기한(1년) 알림
- ⚠️ **`/privacy`의 미확정 3건(보호책임자·보유기간·위탁 고지)이 확정되기 전에는 운영 데이터를 받지 않는다**
  (`docs/NEXT.md` §3)

### S8. 인수인계

- 스크린샷 기반 운영 매뉴얼 (`context/ops/runbook.md`에 추가)
- 미디어팀 2명과 **실제로 한 번 같이 해보기** — 공지 올리기 · 배너 바꾸기. 옵션 B의 존재 이유가 이 테스트다

## 4. 완료 기준

1. 미디어팀이 **매뉴얼 없이** 공지 1건 게시 · 배너 1장 교체를 끝낸다
2. 배포 없이 반영된다
3. anon 키로 개인정보 테이블이 읽히지 않는다 (RLS 확인)

## 5. 대략의 규모

S1~S3(기반·골격)이 덩어리고, S4~S6은 그 위에서 비교적 빠르다. S7은 개인정보 검토가 붙어 별도로 본다.
**공지·배너까지만(S1~S6)이 1차 목표**, S7~S8은 오픈 일정에 맞춰 붙인다.

## 1. 바로 착수 가능 (외부 대기 없음 · 우선순위 순)

### 1-1. ★ Vercel 배포 확인 — 디자이너 확인 링크

디자이너 가이드에 **"이번 주 안에 인터넷 주소로 올려 링크를 보내겠다"고 적어 발송**했다. 이게 없으면
Phase 1(로고·영상) 요청이 공중에 뜬다. 배포가 성공하면 링크 회신.
Supabase 미연결이라 환경변수 없이도 빌드된다 (폼은 "접수 준비 중" 안내만 뜨는 상태).

### 1-2. `/ministry` 기관 페이지 템플릿 확정 (구 Phase 1-1)

작업플랜 §6 Phase 1의 기준 화면. 2차 목차 승계로 라우트가 `/care/welfare` → **`/ministry#welfare` 앵커**로 바뀌었다.
`OrgSection`(기관 소개 공통 블록: 로고·한 줄 소개·활동사진 4·외부 링크)을 만들어 6기관에 적용.
**이게 확정되는 즉시 교역자에게 "기관별 콘텐츠 슬롯 명세서"를 발송**해서 콘텐츠 리드타임을 시작해야 한다
(순서를 뒤집으면 몇 주 손실). 외부 링크 URL은 작업플랜 §1에 확보돼 있음.

### 1-3. 게시판형 라우트 목록 UI (주보·공지·소식 4종·자료실)

전부 "누적 + 페이지네이션" 같은 구조라 **목록 컴포넌트 하나로 6개 라우트를 덮을 수 있다.**
Supabase 전이라 목업 데이터로 만들고, 테이블 연결은 나중에 갈아끼운다.
관련 스키마: `context/03-data-model.md` §4 `bulletins` · §5 `posts`.

### 1-4. `/dev/gnb` 검토 랩 정리

디자이너 합의가 끝났는데 랩은 아직 A/B/C 3안 + 정책 4안 비교 화면이다.
`components/dev/gnb-lab.tsx` 상단 주석대로 **결정 확정 후 삭제**가 원래 계획.
모바일 안을 다시 보여줄 창구로 쓸 수도 있으니 → **삭제 vs 확정안 프리뷰로 축소**는 사용자 판단 필요.

### 1-5. 실내 길찾기(wayfind) 본 개발 이식 + 토큰 리스킨

`prototypes/wayfind`는 라우팅 데이터·알고리즘까지 완성·잠금 상태. **프레젠테이션(색·타이포·애니메이션·팬줌 UX)은 비잠금**이라
우리 토큰으로 리스킨해서 옮기면 된다. 명세 단일 출처 = `prototypes/wayfind/README.md`,
잠긴 결정 = `context/features/wayfinding.md`. 배치는 `/intro#wayfind`와 `/newcomer#wayfind` 두 곳.

## 3. 🔴 착수 금지 (결론 없이 손대면 안 되는 것)

1. **보안지역(특수지역) 선교사 지도** — 실명·파송국가·사진 공개는 선교사 안전 문제. 선교회 담당자 확인 전
   `/ministry#mission` 지도 위젯 착수 금지. (작업플랜 §2 B-2 · 디자이너 가이드 Phase 3에도 보류로 명시함)
2. **새가족 수료자 실명 명단** — 공개 웹 게시는 개인정보 이슈. 어드민 내부 또는 "N명"만 노출 권고. (§2 B-1)
   `lib/nav.ts`의 `UNPLACED`에 유일하게 남아 있는 항목.
3. **RLS 미설계 테이블에 운영 데이터 투입** — `guardrails/04-security-privacy.md`.
   폼 4종의 Server Action은 환경변수가 없으면 **성공으로 위장하지 않고** 접수 불가를 반환하도록 돼 있다. 그대로 둘 것.
4. `> DECISION NEEDED:` 마커가 붙은 디자인 토큰을 쓰는 컴포넌트 신규 제작.

## 2. 바로 착수 가능 (외부 대기 없음 · 우선순위 순)

### 2-1. ★ 2차 목차 승계 — `lib/nav-v2.ts` → `lib/nav.ts` + 빠진 라우트 스텁

**왜 첫 번째인가:** 지금 메가메뉴는 B안 구조(좌측 메뉴명 / 우측 하위)인데 데이터가 1차 목차라
그룹 없이 평평한 목록 4~7개만 뜬다. 2차 목차는 대메뉴마다 L2 그룹 2~3개가 있어서
**데이터를 갈아끼우는 순간 패널이 설계 의도대로 채워진다.** 이후 모든 페이지 작업의 전제이기도 하다.

- `lib/nav-v2.ts`의 `NavSection`은 `groups[]` 구조 → 헤더 우측을 그룹별 열로 렌더하도록 수정 필요
  (지금은 `children[]` 평면을 3열 그리드로 뿌림)
- 새로 생기는 라우트: `/education` `/ministry` `/worship/live` `/activity/{bulletin,video-news,news,members,denomination}` `/activity/weekly`
  → **먼저 `StubPage` 만들고 스텁 페이지부터** 깔아야 메가메뉴에서 404가 안 난다
- `lib/nav-v2.ts`의 `UNPLACED` 4항목은 아직 자리 없음 (§3 회신 대기와 연결)
- 완료 후 `lib/nav-v2.ts` 삭제하고 `lib/nav.ts` 하나로 되돌릴 것

### 2-2. 온라인 새가족 등록 폼 노출 중단 (결정만 있고 코드·문서 미적용)

2026-08-09 결정 = **1차 오픈 범위 제외, 코드는 삭제하지 말고 노출만 중단.** 근거는 `lib/nav-v2.ts` 주석 2항
("`새가족 등록` 항목 삭제 — 온라인 유입 안 하기로 결론"). 온라인 접점은 카카오채널·전화가 대신한다.

- `lib/nav.ts` `새가족 등록` 항목 주석 처리 (복구법을 주석으로 남길 것)
- `app/(site)/newcomer/page.tsx`의 `overrides={{ register: <NewcomerForm /> }}` 제거 (동일하게 주석 보존)
- `context/04-information-architecture.md` §6 항목 4번(새가족 온라인 등록 폼) 갱신 — 지금 살아 있는 것으로 적혀 있음
- 폼 코드·스키마·서버액션은 **보존** (`app/_actions/newcomer.ts`의 INSERT는 여전히 TODO 스텁이라 오작동 위험 없음)

### 2-3. `/dev/gnb` 검토 랩 정리

디자이너 합의가 끝났는데 랩은 아직 A/B/C 3안 + 정책 4안 비교 화면이다.
`components/dev/gnb-lab.tsx` 상단 주석대로 **결정 확정 후 삭제**가 원래 계획.
다만 모바일 안을 다시 보여줄 창구로 쓸 수도 있으니 → **삭제 vs 확정안 프리뷰로 축소**는 사용자 판단 필요.

### 2-4. Phase 1-1 — `/care/welfare` (경향복지재단) + `OrgSection` 템플릿 확정

작업플랜 §6 Phase 1의 기준 화면. **이게 확정되는 즉시 교역자에게 "기관별 콘텐츠 슬롯 명세서"를 발송**해서
콘텐츠 리드타임을 시작해야 한다 (순서를 뒤집으면 몇 주 손실). 외부 링크 URL은 작업플랜 §1에 이미 확보돼 있음.

### 2-6. 실내 길찾기(wayfind) 본 개발 이식 + 토큰 리스킨

`prototypes/wayfind`는 라우팅 데이터·알고리즘까지 완성·잠금 상태. **프레젠테이션(색·타이포·애니메이션·팬줌 UX)은 비잠금**이라
우리 토큰으로 리스킨해서 옮기면 된다. 명세 단일 출처 = `prototypes/wayfind/README.md`,
